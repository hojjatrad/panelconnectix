ROOT CAUSE

  • 10 URL: هر کدام 15% fail و از 0 شروع → کاربر میبینه 15% → 0% → 15% → لوپ
  • Timeout کوتاه: 12s send + 20s stream برای اینترنت ضعیف ایران کمه → timeout تو 15%
  • بدون Resume: هر fail فایل delete و از 0 شروع → حلقه بینهایت
  • Progress برعکس: 5% → 15% → 5% → 15% → کاربر فکر میکنه برمیگرده اول
  • بدون حد: 10 URL * 90 DM تلاش = بینهایت لوپ
  • http.Client ضعیف: برای فایل بزرگ رو اینترنت ناپایدار مناسب نیست

✅ فیکس اساسی و عمیق v4.0.38 - برای همیشه

FUNDAMENTAL FIX PERMANENT

  • فقط 3 URL قابل اعتماد (نه 10): direct.vpbotn.ir (پایدارترین) + vpbotn.ir + GitHub CDN - هر کدام fail همون 15% نمیسازه
  • DownloadManager اول (نه آخر): سیستم اندروید قویتر برای اینترنت ناپایدار - 60 ثانیه + 20 ثانیه تشخیص گیر
  • Resume via Range: اگر 15% fail شد از 15% ادامه نه از 0% - Range: bytes=existingSize- + 206 Partial Content
  • Timeout بزرگ: 30s اولیه + 60s استریم (قبل 12s/20s) برای اینترنت ضعیف ایران
  • Monotonic progress: هیچوقت برنمیگرده عقب - if (p < lastProgress) p = lastProgress - فقط میره جلو
  • Max 3 تلاش بعد مرورگر: بعد 3 تلاش مستقیم مرورگر باز میشه - هیچوقت حلقه بینهایت نه
  • Exponential backoff + jitter: بین تلاش‌ها 2s, 4s, 8s صبر + رندوم
  • فایل ناقص نگه دار: رو stream error delete نکن - نگه دار برای resume بعدی
  • سرور Accept-Ranges: .htaccess Header set Accept-Ranges bytes - سرور resume ساپورت کنه
  • مرورگر فوری: بعد 3 تلاش openBrowser(directUrl) - 100% کار میکنه چون DM سیستم قویتره

نتیجه: دیگه هیچوقت 15% → 0% → 15% لوپ نداری - یا resume از 15% ادامه میده یا بعد 3 تلاش مرورگر باز میشه که 100% کار میکنه
